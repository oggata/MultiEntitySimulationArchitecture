# エージェント住宅のGLBキャッシュ最適化

## 概要

エージェントの住宅は、マップ上で**最も重複が多い3Dモデル**です。すべての住宅が同じGLBファイル (`ComfyUI_00004_.glb`) を使用しているため、キャッシュシステムの効果が最大限に発揮されます。

## 実装前の状況

### 問題点
```javascript
// 住宅が48軒ある場合...
住宅1: ComfyUI_00004_.glb を読み込み (100ms)
住宅2: ComfyUI_00004_.glb を読み込み (100ms)
住宅3: ComfyUI_00004_.glb を読み込み (100ms)
...
住宅48: ComfyUI_00004_.glb を読み込み (100ms)

合計読み込み時間: 約4800ms (4.8秒)
ファイルアクセス: 48回
```

### パフォーマンス問題
- 同じファイルを48回も読み込む無駄
- ネットワーク/ディスクI/Oの過剰な負荷
- マップ読み込みに数秒かかる
- ユーザーエクスペリエンスの低下

## 実装後の改善

### キャッシュの効果
```javascript
// キャッシュシステム使用時

住宅3: キャッシュから取得 (1ms)
...
住宅48: キャッシュから取得 (1ms)

```

## メモリ使用量

### キャッシュのメモリ効率

```
元のGLBモデル（キャッシュ）: 1つ（約500KB）
各住宅のクローン: 軽量なインスタンス × 48

合計メモリ: 元データ1つ + 軽量なクローン48個
```

### 従来の方法との比較
- **従来**: 各住宅が独立したデータを持つ → 重複が多い
- **キャッシュ**: 元データは1つだけ、クローンは参照が中心 → 効率的

## 実装の特徴

### 1. 自動キャッシュ管理
- 初回アクセス時に自動でキャッシュに保存
- 2回目以降は自動でキャッシュから取得
- 開発者は意識する必要なし

### 2. 並列読み込み対応
```javascript
// 複数の住宅が同時に生成されても安全
createAgentHome(homeData1);  // ← ファイル読み込み開始
createAgentHome(homeData2);  // ← 読み込み待機
createAgentHome(homeData3);  // ← 読み込み待機
// → すべて同じPromiseを待つため、重複読み込みなし
```

### 3. エラーハンドリング
- キャッシュ読み込み失敗時は自動でフォールバック
- 従来と同じ安全性を維持
